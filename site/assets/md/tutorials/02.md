# 教程 02 · 内置 Agent 原理与接入

> 目标：看懂"为什么不用 node_exporter 而自研 Agent"、Agent 采集了什么、上报协议怎么定义的、
> 断网怎么办、以及**自己写一个探活/采集扩展**要改哪里。
> 代码：`agent/agent_main.py`（单文件、无第三方依赖，除 psutil/httpx）、`agent/install.sh`。

## 1. 为什么自研（而不是直接用 exporter 生态）

调研结论（`docs/02-调研/`）：没有任何**单件**开源同时覆盖"指标 + 探活 + 证书到期 + 进程存活"，
而营销文案又必须"一条命令接入"。所以定位是：

| 场景 | 走哪条轨 |
|---|---|
| 没有现成监控、要 30 分钟出效果 | **轨 A：内置 Agent**（默认） |
| 已有 Prometheus/node_exporter | **轨 B：Prom 对接**（数据源 + 查询代理 + prom 作用域规则） |
| 想把 exporter 的 `/metrics` 直接拉进平台 | 轨 B+（V1.5，见教程 10） |

轨 A 的取舍：自研带来的一点复杂度，换"分发闭环"（安装令牌、指纹、自启、卸载）和
"多类型探活"这两件 exporter 不给你的东西。

## 2. 采集了什么

```python
# agent/agent_main.py（节选）
cpu   = psutil.cpu_percent(interval=0.3)
mem   = psutil.virtual_memory().percent
disk  = psutil.disk_usage("/").percent
load  = psutil.getloadavg()[0]
net   = psutil.net_io_counters()      # → net.bytes_sent / net.bytes_recv
```

指标名与语义（**别改名字**，规则/巡检/大盘都按这些名字取值；平台侧把这份名字写成
`app/services/ingest.py: AGENT_METRIC_CONTRACT`，并由契约测试守着 Agent 源码不漂移）：

> ⚠️ 实测教训：Agent 早期上报的是 `load.load1` 和 `disk{mnt}.percent`，而平台用 `load.1` / `disk.percent`
> —— 名字对不上，**内置 Agent 采的磁盘与负载在平台上永远读不到**（磁盘类规则、巡检的磁盘/负载两项、
> 大盘负载图全空白）。修好后才对齐。改指标名时务必同时改平台侧契约与规则文档。

| 指标 | 含义 | 单位 |
|---|---|---|
| `cpu.percent` | CPU 使用率 | % |
| `mem.percent` | 内存使用率 | % |
| `disk.percent` | 根分区使用率 | % |
| `load.1` | 1 分钟平均负载 | 核数无关的原始值 |
| `net.bytes_sent` / `net.bytes_recv` | 网卡累计字节 | bytes（累计值，看斜率） |

**探活四类**（`probes` 配置，由平台下发或本地配）：

| type | 判据 | 值语义 |
|---|---|---|
| `http` | GET 目标，2xx/3xx 算 up | latency_ms |
| `tcp` | 建连成功算 up | latency_ms |
| `process` | 按进程名/cmdline 匹配（排除自身与父进程） | 命中数（>0 算 up） |
| `https-cert` | TLS 握手取证书 | **剩余天数**（注意：这个取值和前三个不是一个量纲，规则里别混用） |

## 3. 上报协议（平台侧契约）

平台只认两个端点，都是**机器凭证**（`X-Ident` + `X-Token`），不用户 JWT：

```
POST /api/ops/agents/register   {fingerprint, hostname, ip, os, agent_version, install_token?} → {ident, token}
POST /api/ops/agents/metrics    {ts, metrics:[{metric,value}], probes:[{name,type,target,status,latency_ms}]} → 204
POST /api/ops/agents/heartbeat  {agent_version?} → 200          # 只刷 last_beat，不带数据
```

- `ident = sha256(fingerprint)[:32]`（32 位十六进制）。**人/AI 说的是主机名**，平台的诊断工具
  两者都认（ident 精确 → name 精确 → 唯一前缀）。
- `install_token` **只在首次接触时校验**（已注册主机重启/重装免令牌），避免"重启一次就要重新发令牌"。
- 默认 15s 一个点；`metrics.ts` 用 UTC ISO 串。

## 4. 离线缓存与续传（拔网线不丢数据）

Agent 内置 SQLite 缓冲：

```python
cache_limit = max(3600 // args.interval, 10)   # 按"1 小时的数据量"换算条数上限
# 上报失败 → cache_push(payload)（超限淘汰最老）
# 上报成功 → cache_pop_batch(50) 循环续传
```

所以：**断网 10 分钟恢复后，数据会补齐**（这是 FR-B1 的验收项之一）。缓冲上限按 1 小时设计，
更久的断网会丢最早的样本（这是有意的取舍：避免 Agent 磁盘无限增长）。

## 5. 安装脚本做了什么

`install.sh` 支持 `--server / --token|--install-token / --interval / --probes / --agent-dir / --uninstall`，
关键处理：

1. **解释器自动选择**：`python3.13→3.12→…→python3`，逐个检查版本 ≥3.9
   （真机实测：Alibaba Cloud Linux 3 自带 python3 是 **3.6**，直接跑会语法错）；
2. pip 兜底链：`pip3` → `python -m pip` → `ensurepip` → `--break-system-packages`，失败给可执行指引；
3. `curl | bash` 场景下自己会去 `$SERVER/agent_main.py` 下载主程序（`$0` 不是文件，不能 `cp`）；
4. Linux 用 systemd（先 `sudo -n` 探测，无权限则给出手工命令）、macOS 用 `launchctl bootstrap`；
5. `--uninstall` 真的会停服务、删 unit/plist、删目录。

## 7. 常见问题

| 现象 | 原因 | 处理 |
|---|---|---|
| 主机一直离线 | 心跳超 `3 × interval`（默认 45s）判 offline | 看 Agent 日志；确认目标机到平台 8848 通 |
| 指标图有洞 | Agent 重启 / 断网超过缓冲上限 | 看 `cache` 表行数；调大 `--interval` 反而更稳 |
| 进程探活一直 unknown | Agent 版本过旧（早期无 `process` 分支） | 升级到当前版本 |
| 同一台机器出现两条主机 | 指纹变了（换网卡/容器重建） | 容器/不可变基建请固定 `AIOPS_FINGERPRINT` |
| 主机名对不上 incident | 早期种子把主机名写进了 `host_ident` | 跑 `python scripts/repair_demo_data.py --apply` |
