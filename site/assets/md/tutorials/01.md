# 教程 01 · 30 分钟部署与验收

> 目标：从零到"打开浏览器能看到真实数据、能触发一条真实告警"，并留下可核对的验收证据。
> 适用：Ubuntu 22.04/24.04、Debian 12、Rocky 9、macOS（本地体验）。
> 资源：2C4G 起步（实测 1C2G 也能跑演示，但不建议带 100 主机）。

## 0. 你要准备什么

| 项 | 说明 |
|---|---|
| Docker + Docker Compose | `docker compose version` 能看到 v2 |
| 一个 LLM API Key（可选） | 不填也能跑：**告警、采集、大盘不受影响**，只是 AI 诊断/ChatOps 会明确报错（不会静默假成功） |
| 端口 | 平台 8848；SeekDB 2891（只监听本机建议） |

## 1. 三条命令起来

```bash
git clone <你的仓库地址> aiops-platform && cd aiops-platform
cp .env.example .env          # 填 LLM_BASE_URL / LLM_API_KEY / LLM_MODEL_MAIN（不填也行）
docker compose --env-file .env -f deploy/docker-compose.yaml up -d --build
```

> ⚠️ **必须带 `--env-file .env`**。`-f` 指向 `deploy/` 子目录时，compose 的项目目录会变成
> `deploy/`，根 `.env` 不会被自动读取 → `LLM_*` 全是空值，AI 功能"看起来没反应"。

起来后：

```bash
docker compose --env-file .env -f deploy/docker-compose.yaml ps      # 4 个容器都 Up
curl -s http://127.0.0.1:8848/api/health                              # {"code":0,...,"status":"up"}
```

浏览器打开 http://127.0.0.1:8848 ，`admin / admin123`（**首登必须改密码**）。
点「演示模式一键进入」是只读体验；AI 助手对演示账号是否开放由 `DEMO_CHAT_ENABLED` 决定。

## 2. 种子数据（首屏不空）

compose 里的两台模拟主机（`mock-web-01` / `mock-db-01`）自己会上报，所以**磁盘/CPU 图表马上有数据**。
想让问题看板、案例库、历史趋势都有内容，跑一次种子：

```bash
docker compose --env-file .env -f deploy/docker-compose.yaml exec platform \
  python scripts/seed_demo.py --days 7
```

它会：注册 4 台演示主机（demo-web-01/02、demo-db-01、demo-cache-01）→ 按 **Agent 上报协议**
回填 7 天 5 分钟粒度指标（走的是和真实采集同一条链路，不是直接写库）→ 建演示规则 →
写历史事件与案例卡（含向量）。

## 3. 触发一条真实故障（4 分钟全链路）

```bash
bash deploy/faults/cpu_spike.sh          # CPU 飙高，180s 后自动恢复
```

观察顺序（这就是产品的卖点链路）：

1. **告警中心**：十几秒内弹出实时告警（SSE，不用刷新）；
2. **问题看板**：多条同源告警被收敛成 1 个 incident（时间窗 + 指纹 + LLM 因果判定）；
3. **事件详情 → 一键诊断**：右侧实时滚动"AI 在想什么 + 工具调用瀑布"，结束后出报告；
4. **处置与变更**：从报告的 `## VALIDATED FIXES` 生成变更单（五段：风险/前置检查/步骤/回滚/验证）；
5. **操作审计**：以上每一步都可检索到（含被拒绝的越权操作）。

5 种故障脚本都在 `deploy/faults/`（cpu_spike / disk_full / mem_leak / probe_fail / process_hang），
每种一条命令、跑完自愈。完整演示脚本见 `docs/04-交付与运营/演示脚本.md`。

## 4. 接入你自己的机器（一条命令）

在平台「系统设置 → Agent 接入」点生成安装令牌，然后在**目标机**上：

```bash
curl -fsSL http://<平台地址>:8848/install.sh | bash -s -- --server http://<平台地址>:8848 --install-token <令牌>
```

脚本会：探测 Python（3.13→3.9，**系统自带 3.6 也能自动找到可用解释器**）→ 下载 `agent_main.py`
→ 注册（机器指纹 = node + machine-id + 网卡 MAC，可用 `AIOPS_FINGERPRINT` 覆盖）→ 注册 systemd/launchd
开机自启。约 60 秒内主机列表出现该机器并开始出图。

卸载：`curl -fsSL .../install.sh | bash -s -- --uninstall`。

> 目标机自测（不依赖平台）：`bash deploy/verify-agent-install.sh` —— 自带 stub 平台，
> 11 项断言验完整安装链路（含 systemd enable/active、注册与上报是否真的收到）。

## 5. 验收清单（照着打勾）

| # | 验收项 | 怎么验 | 期望 |
|---|---|---|---|
| 1 | 部署 | `docker compose ps` | 4 容器 Up，health 返回 up |
| 2 | 一键接入 | 目标机 install.sh | ≤60s 出现在主机列表 |
| 3 | 实时告警 | 注入故障 | ≤1 个评估周期内弹告警 |
| 4 | 指纹状态机 | 杀进程重启平台 | 活跃告警不丢、不误报恢复 |
| 5 | 收敛 | 一次故障 ≥3 条告警 | 合成 1 个 incident |
| 6 | AI 诊断 | 事件详情点诊断 | 报告带证据引用、四段齐全、结论三档之一 |
| 7 | 处置闭环 | 生成变更单 → 执行只读步骤 | action_audit 有记录；非只读需审批 |
| 8 | 审计 | 操作审计页 | 写操作可检索（含 perm_denied） |
| 9 | 性能 | `python scripts/bench_100_hosts.py --hosts 100` | 评估周期 P95 < 2s（实测 ~100ms） |
| 10 | 成本闸门 | 设 `LLM_DAILY_TOKEN_LIMIT` 调小 | 超限 429 且提示可读 |

## 6. 常见坑（都踩过）

| 现象 | 原因 | 处理 |
|---|---|---|
| 容器起不来 / 立刻退出 | SeekDB 镜像入口把参数当 **SQL** 执行 | 不要给 seekdb 服务传 `command` |
| `Unknown database 'aiops'` | SeekDB 无自动建库 | 平台启动命令已含 `scripts/db_init.py`（幂等，带重试） |
| AI 功能报 `LLM_UNAVAILABLE` | 没配模型 | 系统设置页加配置，或填 `.env` 的 `LLM_*` |
| AI 报 `LLM_QUOTA_EXCEEDED` | 当日配额用尽 | 调 `LLM_DAILY_TOKEN_LIMIT`（0=不限），UTC 次日自动重置 |
| 前端页面空白 | 某个 JS 模块语法错（ESM 整体失败） | `node --check static/js/pages/*.js`；或跑 `pytest tests/test_d3_frontend_assets.py` |
| 时间显示成"-27896 秒前" | 数据库会话时区不是 UTC | 连接串已带 `init_command=SET time_zone='+00:00'`，勿手工去掉 |
| 本机有**两个** 2891 | 原生 seekdb(IPv4) 与 docker 映射(IPv6) 并存 | `SELECT MAX(id) FROM audit_logs` 对一下，确认连的是哪个库 |
