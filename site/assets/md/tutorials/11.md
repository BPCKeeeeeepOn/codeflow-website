> 目标：拿到源码后能自己加页面、加接口、加诊断工具、加通知渠道、加迁移，并且知道改动边界在哪。

分层纪律：**router 只做参数与权限 → service 做业务 → model 做持久化**。
引擎（`engine/`）只依赖 service 与 model，不反向依赖 router。

## 2. 加一个 API（5 分钟）

```python
# backend/app/routers/hosts_extra.py（或加到现有 router）
from fastapi import APIRouter, Depends, HTTPException
from app.core.security import require
from app.db.session import get_db
from app.models.shell import User

router = APIRouter(prefix="/api/ops", tags=["ops-extra"])

@router.get("/hosts/uptime-summary")
async def uptime_summary(db=Depends(get_db), _: User = Depends(require("read"))):
    ...
    return {"code": 0, "msg": "ok", "data": {...}}
```

然后在 `app/main.py` 的 `include_router(...)` 列表里挂上。**必须做三件事**：

1. 选权限级别：`read`（只读）/ `diag`（诊断触发）/ `alert_ops`（告警与事件操作）/ `write`（配置与执行）；`chat` 另有 `require_chat()`；
2. 返回值统一 `{code,msg,data}`；错误用 `raise HTTPException(4xx, "人话")`（全局处理器会统一信封）；
3. 在 `tests/test_d8_api_matrix.py` 的 `ROUTES` 表里登记（**不登记测试会直接失败**——这是我们的覆盖守卫）。

## 3. 加一个前端页面（10 分钟）

```js
// static/js/pages/my_page.js
import { api, can } from "../api.js";
import { h, table, toast } from "../ui.js";
export async function render(root) {
  const canWrite = can("write");            // 按钮可见性一律取自服务端能力集
  const d = await api.get("/api/ops/xxx");  // 统一客户端：错误已 toast，401 自动跳登录
  root.replaceChildren(h("div", {class: "page-head"}, h("h2", {}, "我的页面")), table([...], d.items));
}
export function destroy() {}
```

然后在 `static/index.html` 里：`import * as myPage` → 加进 `PAGES` 与 `TITLES`
（`TITLES` 现在走 i18n 字典，请在 `static/js/i18n.js` 里加 `page.my_page`）→ 侧栏加一个
`<a class="nav-item" data-page="my_page" data-i18n="page.my_page">`。
需要按权限隐藏时，在 `applyNavPerms()` 的 `need` 映射里加 `my_page: "write"`。

改完必须跑：`node --check static/js/pages/my_page.js` + `pytest tests/test_d3_frontend_assets.py`
（前端是免构建 ESM，**一个模块语法错会让整个页面空白**，这个测试就是防它的）。


三条纪律：① **只读**（写操作不能进诊断工具面）；② 拿不到数据要返回 `NO_DATA` + 原因，
不许编；③ 加一条测试（`tests/test_d9_gaps.py` 里有 ident/name 互认的现成写法）。

## 5. 加一个通知渠道类型

友好类型（飞书/钉钉/邮件/Webhook）走 `notify_transport.to_apprise_url()` 的映射；
其它 150+ 渠道用 **`config_json.apprise_url` 逃生口**（`slack://`、`telegram://`…）。

要新增"友好类型"（比如企业微信）：

```python
# app/services/notify_transport.py
FRIENDLY_TYPES = ("feishu", "dingtalk", "email", "webhook", "wecom")   # ← 加名字
def to_apprise_url(ch_type, cfg):
    if ch_type == "wecom":
        tok = cfg.get("webhook_url", "").rsplit("key=", 1)[-1]
        return f"wxteams://..."   # 具体 scheme 查 apprise 文档
```

`validate_channel()` 会用它做创建时校验（不合法 → 400 人话，不再撞数据库）。

## 6. 加一次数据库迁移

```bash
cd backend
../.venv/bin/python -m alembic revision -m "d10 add xxx"     # 生成空迁移
# 手写 upgrade()/downgrade()（这里不用 autogenerate：SeekDB 的索引反射不可靠，见 04 §10）
../.venv/bin/python -m alembic upgrade head
```

SeekDB 禁忌（都是实测教训，文档在 `04-数据库设计说明书.md`）：
1. 建索引要**手写**（`BLOCK_SIZE` 语法会让 SQLAlchemy 索引反射崩）；
2. **VECTOR 列**会让 ORM 反射崩 → 该表走 raw SQL，并在 `migrations/env.py` 的 `_NO_REFLECT` 里登记；
3. **ENUM 列做索引首列 + 等值过滤** → `(1210, 'Invalid argument')` → 索引首列用 INT；
4. 引擎连接串必须带 `init_command=SET time_zone='+00:00'`（否则时间显示成"-27896 秒前"）。

## 7. 改动的验收流程（别跳）

```bash
cd backend
../.venv/bin/python -m pytest -q tests          # 99 项，约 20s（务必在 backend 目录下跑）
node --check ../static/js/pages/你的页面.js      # 前端改了就检查
cd .. && docker compose --env-file .env -f deploy/docker-compose.yaml up -d --build platform   # 容器实测
bash deploy/faults/cpu_spike.sh                  # 触发一条真故障验证链路没断
```

测试目录纪律：**不要在页面里按 role 硬编码按钮可见性**（用 `can()`）；
**不要在诊断/巡检工具里做写操作**；**改报告模板必须跑 findings 校验测试**。

## 8. 想扩展时的边界（V1 有意不做）

多租户、日志/链路追踪、K8s 深度诊断、值班排班、插件市场、自定义仪表盘、
远程命令执行通道、告警订阅规则改写事件、多 Agent 编排（triage/dispatch）、
活文档 artifacts、知识库 memory 层。取舍依据在 `docs/02-调研/竞品对比与突围策略.md`，
不要"顺手加"——每加一项都要考虑它对 2C4G 单机部署的影响。
