# 教程 10 · 多模型对接与成本治理

> 目标：怎么接任意 OpenAI 兼容模型、api_key 怎么存、用量怎么分账、
> 配额怎么设、降级链路长什么样。
> 代码：`app/services/llm_gateway.py`、`app/routers/shell.py`、`app/routers/prom.py`。

## 1. 接一个模型（两种方式）

**方式 A：系统设置页（推荐，落库加密）** → 「系统设置 → LLM → 新增模型配置」，填
`name / provider / base_url / api_key / model / fast_model / extra_config(JSON)`，
点「测试」确认连通。可以配多个，`is_default` 决定默认用哪个。

**方式 B：环境变量兜底**（无 DB 配置时生效，适合容器化部署）：

```bash
LLM_BASE_URL=https://api.minimaxi.com/v1
LLM_API_KEY=sk-...
LLM_MODEL_MAIN=MiniMax-M3
LLM_MODEL_FAST=MiniMax-M2.7-highspeed
```

选择顺序：DB 里 `enabled` 的配置（取 `is_default`，否则第一条）→ 都没有则用 env 兜底
→ 都没有则明确报 `LLM_UNAVAILABLE`（**不会静默假成功**）。

## 2. 安全：api_key 怎么存

```
库列 api_key_encrypted：nonce(12B).hex + "." + ciphertext.hex     # AES-GCM
密钥来源：KEY_STORE_SECRET（环境变量；AESGCM 用其前 32 字节）
日志：列表接口只回掩码（***），api_key 不出现在任何响应/日志里
```

两个实测坑：
1. **KEY_STORE_SECRET 必须稳定**：换值之后旧密文解不开，症状是
   `InvalidTag`（异常消息是空字符串！）→ 表现为"AI 功能莫名报错"。所以
   配置解析已锚定 `backend/.env`（不随当前工作目录变），换密钥请重新保存模型配置；
2. 容器部署别依赖"当前目录的 .env"：容器里用**环境变量**/compose 的 `environment` 传。

## 3. 用量分账与配额

每次调用都写 `llm_usage`：`purpose`（rca/chat/summary/inspect/fixcheck/embed）+
`model` + prompt/completion/total tokens + 时间。

```bash
GET /api/llm-configs/usage?days=7
# → {items:[{day,purpose,total_tokens}], quota:{limit,used,remaining,scope,exceeded,resets_at}}
```

配额（非功能需求 §8.3 的"演示站每日 token 限额"）：

| 变量 | 语义 |
|---|---|
| `LLM_DAILY_TOKEN_LIMIT` | 全局每日上限，`0` = 不限 |
| `DEMO_DAILY_TOKEN_LIMIT` | demo 角色每日上限（与全局取更严者），默认 200k |

超限行为：**429 + 可读原因**（含"UTC 次日自动重置"与怎么调），不是静默失败。
公开演示站建议：`DEMO_DAILY_TOKEN_LIMIT` 设小一点（如 50k）+ 网关层再限 IP 频次。

## 4. 双模型分工与省 token 的招

| 位置 | 用什么 | 为什么 |
|---|---|---|
| 诊断主循环、ChatOps 回答 | main | 要推理质量 |
| 工具输出摘要、历史压缩 | fast | 机械活，便宜模型足够 |
| 告警一句话摘要 | fast | 每条告警都要跑，必须便宜 |
| 巡检日报润色 | fast | 固定句式 |
| 向量化（案例卡） | embedding 模型 | 与 `case_cards.embedding VECTOR(1536)` 维度必须一致 |

省 token 的招（都在代码里）：
1. 工具输出**超限落盘**（只给路径 + 预览），别把 10 万字符塞进上下文；
2. 历史**超阈值压缩**（fast 模型摘要，且压缩后仍记住曾溢出的调用，继续拒绝重复）；
3. 对话只注入**技能索引**（一行/技能），需要时才 `load_skill` 拉全文；
4. 告警风暴时**摘要让路**（队深 > 50 跳过）——成本与可用性的取舍；
5. 诊断有 `max_steps` 与整体 deadline，跑不飞。

## 5. 降级总表（LLM 不可用时系统仍然可用）

| 能力 | LLM 不可用时 |
|---|---|
| 采集 / 大盘 / 主机 | 完全不受影响 |
| 告警触发 / 通知 / SSE | 完全不受影响（摘要静默跳过） |
| 收敛聚类 | 退化为纯规则聚类（同机同窗并入），`CLUSTER_LLM_ENABLED=false` 可强制 |
| 巡检 | 出纯模板日报（无润色段） |
| AI 诊断 | 明确报错并写 `status=failed` 的 stub（不假装有结论） |
| ChatOps | 明确报 `LLM_UNAVAILABLE` / `LLM_QUOTA_EXCEEDED` |
| 案例向量召回 | 降级文本匹配，并如实标注 `mode=text` |

设计原则：**AI 是增值功能，不是单点故障**。任何 LLM 故障都不允许影响"发现→通知"这条生命线。

## 6. Prometheus 对接（轨 B）

```bash
# 1) 加数据源（URL + 认证 + 超时）
POST /api/ops/prom-datasources  {"name":"prod-prom","base_url":"http://prom:9090","auth_type":"none"}
POST /api/ops/prom-datasources/{id}/test
# 2) 即时查询代理（浏览器直连 Prom 也行，但走代理更安全）
GET /api/ops/prom/query?datasource_id=1&query=up&minutes=30
# 3) 建 prom 作用域规则（评估走 Prom API，数据不落本地库）
POST /api/ops/alert-rules  {"scope":"prom","datasource_id":1,"queries_json":["rate(node_cpu_seconds_total[5m])"],"expr":">0.9"}
```

prom 规则的取值走 `detect_labeled()`（保留 Prom 的序列标签 → 能回指到具体 instance）。
数据源不可达时**跳过本轮评估**（不当作"指纹消失"），避免误报恢复。
