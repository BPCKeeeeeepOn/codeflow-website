# 教程 09 · 定时巡检与健康日报

> 目标：巡检项清单、cron 调度、日报怎么生成、风险怎么自动进问题看板，以及
> **"未检查"为什么必须如实写**。
> 代码：`app/services/inspect.py`、`app/sched.py: job_reconcile_inspections`。

## 1. 调度：对账式注册，不是"建一次 job"

```python
# app/sched.py 每 60s
async def job_reconcile_inspections():
    rows = 启用的巡检任务
    移除：已删除/停用的 job
    新增：新任务 → CronTrigger.from_crontab(cron_expr) → add_job(_run_inspection_job, max_instances=1)
```

好处与告警规则对账同理：**改 cron / 停用 / 删除都自动生效**，坏 cron 只跳过该任务
（留 warning），不影响其它任务。`max_instances=1` 保证上一轮没跑完不会叠。

默认种子任务：`每日主机巡检`，`0 9 * * *`（UTC）。

## 2. 检查项（8 类）

| key | 判据 | 取值来源 |
|---|---|---|
| `disk` | 根分区 > 85% | `disk.percent` |
| `mem` | 内存 > 90% | `mem.percent` |
| `cpu` | CPU > 90% | `cpu.percent` |
| `load` | 1 分钟负载 > 8 | `load.1` |
| `cert` | 证书剩余天数 < 15 | 探活 `https-cert` 的 `last_latency_ms` |
| `probe` | 存在失败探活 | `probes.last_status` |
| `probe_rate` | **探活成功率 < 90%**（up/总数） | 按主机汇总 |
| `proc` | 异常进程（单进程 CPU > 80% 或 RSS > 2GB） | **仅平台自身主机**（`ps`） |
| `offline` | 主机离线（心跳超 45s） | `hosts.status` |

时间窗：指标取**最近 15 分钟**的最新值（不是平均值——巡检要回答"现在有没有问题"）。

## 3. "未检查"是必须的诚实

`proc` 项在远程主机上**做不到**（V1 Agent 不上报进程清单）。所以：

```python
if not 平台自身主机:
    row["items"].append({"key": "proc", "value": "未检查（远程主机）", "bad": False, "skipped": True})
```

报告里会如实显示"未检查（远程主机）"，而**不是**填个"正常"。这与诊断工具的边界一致
（`read_log_tail` 对远程主机返回 NO_DATA 而不是编造日志）。做巡检类产品时这条最容易被忽略，
但它决定了报告能不能被信任。

## 4. 日报长什么样

`_render_report()` 输出：标题 + 摘要（主机数/异常项/结论）→ **主机明细表**
（状态 / CPU% / 内存% / 磁盘% / 负载1m / 探活成功率 / 异常进程）→ 异常项清单；
最后用 fast_model **只根据给出的事实**润色一段"关键风险与建议关注点"（不超过 200 字，
系统提示词明确"只依据给出的数据，不要臆测"）。LLM 不可用时就是纯模板报表（不报错）。

## 5. 风险自动进问题看板

巡检发现异常时，按"主机 + 检查项"自动建 incident（`cluster_reason=demo_seed`/`inspect`），
于是巡检风险会出现在问题看板里，可以被**一键 AI 诊断**——巡检与诊断闭环连起来。
上限 `anomalies[:20]`：一次巡检开太多事件反而会淹没看板。

## 6. 手动触发

```bash
POST /api/ops/inspections/run-once            # 即时巡检（不落任务表）→ 返回报告
POST /api/ops/inspections/{iid}/run           # 跑指定任务（落 last_run_at/report_md）
GET  /api/ops/inspections/{iid}               # 读最近报告
```

权限：触发是 `diag`（admin/member），任务 CRUD 是 `write`（admin）。

## 7. 排障

| 现象 | 检查 |
|---|---|
| 到点没跑 | `engine-state` 看不到巡检 job → 看 `sched.py` 日志里的"cron 表达式非法"；确认 `enabled` |
| 日报全是"未检查" | 该主机没有指标上报（`metrics/query` 空）→ 是采集问题不是巡检问题 |
| 每天都开一堆事件 | 阈值太松（如磁盘 85% 常态超）→ 调阈值或用 `for_duration` 类规则替代 |
| 报告没有润色段 | LLM 不可用 → 正常降级为纯模板（不影响风险项） |
