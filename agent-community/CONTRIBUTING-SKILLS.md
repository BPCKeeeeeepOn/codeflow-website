# 贡献指南 · 社区技能（SKILL.md）

> 一句话：把你真实排查过的一次故障，写成平台可一键导入的技能。不需要会写代码，但需要真的排查过。

---

## 1. 什么样的技能值得贡献

- **可复用**：这个场景不止你家有——nginx 502、连接池打满、inode 耗尽是全行业共病；
- **有边界**：你知道什么情况下该停手（哪些动作只读、哪些必须走人工）；
- **可验证**：能用平台自带的 5 种故障注入脚本（cpu_spike / mem_leak / disk_full / probe_fail / process_hang）或一次真实事件复现。

**不被接受**：写得太泛（"CPU 高了查一下"）、含写操作命令、要求携带明文凭据、或只有你自己环境才成立的路径。

## 2. 三步流程

1. **提案**：开一个 Issue，讲清适用范围 + 一个真实故障故事。维护者确认"值得"后再动笔，避免写完不收。
2. **起草**：按下面的模板写 `SKILL.md`，提交 PR。
3. **验证合并**：PR 里附一个可复现的触发场景；维护者真机跑通后合并进月度收录。合并 30 天后开始累计真实效果数据（加载次数 / 跟进率 / Token 中位数），在社区页公开展示。

## 3. SKILL.md 模板

```markdown
---
name: your-skill-name          # 小写中划线，唯一
description: 一句话说清"排查什么 + 怎么想"。这是技能被匹配和展示的主要依据，必须具体。
alerts: [cpu.*, 探活失败, 关键词]   # 触发范围：指标通配 / 规则名关键词
commands:                        # 可选：技能授权的只读命令（块数组）
  - df -i
rca_priority: 6                  # 数字越小越先被自动路由（官方核心技能占 1-3，建议 5-9）
---

## 何时用
哪些告警/症状该用这个技能。

## 动作（全部只读）
编号步骤。每步：做什么 → 怎么读结果 → 分叉去哪。

## 边界
不做什么、什么情况要换技能、哪些结论必须交给人工。
```

## 4. 命令硬规则（自动校验，不满足合不进来）

- **全部只读**：首词必须在平台安全动词表内（`df / du / ss / journalctl / systemctl status / docker ps|logs / openssl / curl GET 形状 / mysql -e "select|show" / redis-cli 读命令` 等）；
- **无组合**：不含管道 `|`、分号 `;`、`&&`、反引号、`$(`——串联命令一律拒绝；
- **无写重定向**：`>` `>>` 只允许 `/dev/null`；
- **curl 只认 GET 形状**：`-X/-d/-F/-T/-o/-O` 等变更类参数出现即拒；
- `find` 禁 `-delete/-exec`；`systemctl` 仅允许 `status/is-active/is-failed/list-units/...` 读子命令。
- 命令写进 `commands` 后，平台会在导入时做形状校验；**技能授权的命令仅在本次诊断会话内生效**，会话结束即失效。

> 提示：`timedatectl`、`ethtool` 等尚未进入安全动词表——遇到想用但不允许的命令，在 Issue 里提出，白名单按需扩展。

## 5. 效果数据（贡献者能看到什么）

合并后你的技能会进入月度效果榜候选：**加载次数**（诊断里被自动路由或主动加载的次数）、**跟进率**（报告被人工"跟进"的比例，对照平台基线）、**Token 中位数**。样本 <5 时平台如实显示"样本不足"——我们不让噪声冒充信号。

## 6. 落点

- 官方技能仓库：主仓 `backend/skills/`（PR 目标，通过后随版本分发）
- 社区仓（规划中）：独立公开仓库，月度收录 + 效果榜数据源
