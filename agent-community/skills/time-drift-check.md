## 何时用

- 主机"离线"但网络探活正常（心跳时间戳与实际偏差会导致误判）。
- 跨多台主机对齐日志时间线时（平台的错误上下文与多源时间线按 UTC 对齐，机器时钟错 = 时间线错）。
- 部署前置检查（平台 preflight 有时间偏差项：≤60s 通过 / ≤300s 提醒 / 更大阻断）。

## 动作（全部只读）

1. **本机时钟**：`date`——拿到本机 UTC 时间（配合时区显示）。
2. **同步状态**：`timedatectl status` 能看 `System clock synchronized` 与 NTP 服务状态——但该命令**暂不在平台只读安全动词表**，本技能不内置。诊断时可由 `date` 差值反向推断（差值稳定=时钟没在同步；差值缓慢扩大=NTP 失效），或作为人工补充执行项。
3. **交叉验证**：把本机时间与平台告警时间戳对比（报告里写明两者差值与方向）。诊断 Agent 本身拿得到"当前时间"，可直接做这个差值计算，不需要额外工具。

## 边界

- **不要**在诊断里直接改时间（timedatectl set-ntp / date -s 都是写操作，不在只读白名单）——给出结论与修复建议，执行走人工。
- 漂移 <60s 属正常范围（preflight 口径），报告里如实说"偏差在允许范围"，不要制造假发现。
- 容器内的时钟跟随宿主机——容器时间"错"通常先查宿主机，再查容器 TZ 环境变量（显示时区错 ≠ 时钟错，两者别混）。
