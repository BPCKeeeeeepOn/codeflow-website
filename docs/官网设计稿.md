# TestOps Platform 官网 · 设计稿

> 版本：v1.0 · 2026-10-28
> 状态：首页原型已出（`index.html`，可直接双击打开），其余页面待排期
> 设计依据：《开源产品官网设计研究》（15 个样本拆解）· 平台设计令牌 `static/ops.css`（D50 收敛后口径）
> 硬约束：**所有数字必须真实可追溯**，禁止出现准确率、可用性等无法证明的承诺

## 1. 这一版的设计判断

### 1.1 调研得出的三个结论，直接决定了本设计

| 调研结论 | 对本设计的决定 |
|---|---|
| **信任层是分层的**：单一巨型数字 > 量化成果 > logo 墙 > 制度性信誉 > 具名口碑 | 首页 Hero 放**三个真实数字**（82 秒 / 10 分钟 / 0 入站端口），不放 logo 墙（目前没有可公开的客户 logo，编不得） |
| **"开源 vs 商业"必须三卡并列**（Dify / APIPost / Docker / Plane 共识） | 首屏下方设**部署三卡**：开源 Docker / 私有化 / 商业版，让访客 5 秒自我定位 |
| **差异化必须独占一块，且是别人抄不了的** | 设**证据链专章**（§4）。全平台唯一能做出"只有 TestOps 有"的画面的能力 |

### 1.2 我们**不**做的（和 15 个样本的差别）

| 常见做法 | 我们不做 | 原因 |
|---|---|---|
| 客户 logo 墙 | 不放 | 没有可公开的客户授权 logo。**编 logo 是最容易被拆穿的一类造假** |
| "准确率 95%+" | 不放 | AGENTS.md 红线：宣传不承诺准确率数字 |
| "无人值守自治" | 不放 | 同上。定位是"AI 查清楚，拍板在人" |
| 免费试用倒计时 / 弹窗 | 不做 | 官网是给决策者看的，不是给流量看的 |
| 移动端适配 | 不做 | 平台本身已明确"移动端未适配"，官网不制造假的期待 |

## 2. 信息架构

### 2.0 双层定位（2026-10-28 修订，吸收 TestHub 打法）

官网是**两层结构**，不是单层转化页：

| 层 | 目标 | 承载 | 留存机制 |
|---|---|---|---|
| **产品层**（转化） | 让合适的人部署 | Hero / 部署三卡 / 证据链 / 对比表 | CTA → GitHub → 部署 |
| **知识层**（留存） | 让来过的人反复回来 | 学习学院 / 开源专区 / 教程 / 题库 | **持续更新 + 内容资产复用** |

> TestHub 的启示：它的开源专区（33 个带 star 的精选项目）和 Skills 教程（腾讯文档 + 公众号 + 网盘）让人"愿意来、来了有得学、学了还想来"。**知识层是官网的"回头率"来源，产品层只负责第一眼的转化。**
>
> **我们的独有优势**：主仓 `learning/`（11 篇机制/SRE 文章 + 3 条学习路径）、`docs/05-教程`（12 篇）、`docs/06-面试题库`（46 题）**已经写好了**——知识层不是从零生产，是把已有资产接到官网上并保持更新。

### 2.0.1 留存钩子（内容运营纪律）

| 钩子 | 节奏 | 说明 |
|---|---|---|
| 学习学院文章 | 每周 1 篇新增或修订 | 从 `learning/` 起步（11 篇现成），前沿 AI 主题逐月补 |
| **技能集市（首页 #skills-market）** | 月度收录 + 效果榜 | 见 §2.5（超预期板块：三轨技能目录 + 贡献三步 + 真实效果数据公开） |
| 开源专区收录 | 每月复核一次 | 收录/剔除要有理由；stale 项目如实标注 |
| 《AI 运维月报》 | 每月 1 期 | 赛道动态 + 新收录项目 + 平台发版摘要（可订阅占位：RSS / 邮件） |
| 面试题库增补 | 随版本演进 | 每个大版本附 3-5 道新题（与 D 编号里程碑对应） |
| 学习路径进度 | 按完成度 | 三条路径（值班工程师 4 周 / 中级 SRE 6 周 / 平台开发者 8 周），路径页给逐周清单 |

**诚实边界**：学习学院栏目链接在官网正式上线前指向 GitHub 对应目录（真实可达），不做死链占位页。

### 2.5 技能集市（v1.3 新增；v1.4 随 Agent 评测改造下沉到首页）

> **v1.4 落点变更（2026-10-30）**：导航项"Agent 社区"改名 **"Agent 评测"**，该页改为全屏嵌入 **EvalDeck 评测平台**（见 §2.6）。本节的三轨技能集市**整体下沉到首页 `#skills-market` 板块**（内容与守卫不删，只换落点）：技能卡仍由构建器解析 `agent-community/skills/*.md` frontmatter 生成，卡数=md 数由守卫 **G22** 锁。

**定位**：把一线运维的排查经验，变成人人可导入的技能。SKILL.md 是载体，平台 `import-github`（D173）是导入通道，效果度量（P4）是信任机制。

**与 Dify/n8n 的差异点（调研验证后的两个独有武器）**：
1. **效果数据公开**：每个社区 Skill 卡展示「加载次数 / 跟进率 vs 平台基线 / Token 中位数」——别的社区晒 star，我们晒效果。样本 <5 如实显示"样本不足"，把产品的诚实纪律延伸到社区。
2. **贡献即验证**：PR 必须附可复现的触发场景（平台 5 种故障注入脚本即可），维护者真机验证后合并。安全叙事前置：所有 commands 过只读白名单与九道护栏，会话结束失效。

**首页五区块**：
| 区块 | 内容 |
|---|---|
| 三轨 tab | 官方技能（8 内置，Verified 徽章，含 alerts 范围）｜社区技能（种子 8 张卡：方法论文 + 触发 tag + 效果条 + 导入方式）｜集成配方（exporter 白名单 / MCP 接入 / 通知 recipes，征集中） |
| 贡献三步 | Issue 提案 → 按 SKILL.md 模板起草 → 附验证场景真机合并；合并 30 天后开始累计效果数据 |
| 贡献者墙 | **诚实空态**："还没有社区贡献者——第一个把自己的排查经验写成技能的人，写在这里"（空态本身即留存钩子） |
| 月度效果榜 | 样本不足态："数字够的时候自然会出现在这里，不够的时候我们直说" |
| 安全条 | 命令过只读白名单与九道护栏；denylist 硬边界不可越过；会话结束即失效 |

**内容落点**：`agent-community/skills/` 已备 8 个种子 SKILL.md（nginx-502 / mysql-conn-pool / redis-memory / disk-inode / tcp-timewait / cert-chain / failed-unit / time-drift），全部通过只读命令形状自查（timedatectl 不在安全动词表，已改为 date 差值推断方案）；`agent-community/CONTRIBUTING-SKILLS.md` 为贡献指南骨架。最终归宿二选一：PR 进主仓 `backend/skills/`（官方轨）或独立公开 community-skills 仓（社区轨）。

**竞品纪律**：社区收录的是**方法论内容**（排查步骤），不是工具——与监控告警平台类竞品不同物种，无导流风险；官方/社区标记 + 效果数据防止低质技能砸口碑。

### 2.6 Agent 评测（v1.4 新增）

**定位**：Agent 评测是**通用能力**，不是本产品的附属功能——评测任何接入 OTLP/HTTP 的 Agent，不限于 TestOps 自身。

**形态**：官网 `/agent-community/` 全屏 iframe 嵌入独立部署的 **EvalDeck** 评测平台（品牌加载态先显，iframe onload 后移除，不白屏）。评测平台能力全量可用：

| 能力 | 说明 |
|---|---|
| 11 预置评估器 | Judge = LLM-as-judge（真模型调用，OpenAI/Anthropic 双协议）｜Code = 沙箱 Python（只读白名单 + seatbelt 隔离）｜Human = 标注工作流，结果形状与前两者一致 |
| 轨迹断言 DSL | 七算子 + `assert-set` 嵌套 + `not-` 取反，把"预期路径"写成可执行断言 |
| 实验与门禁 | 多组对照 + 门禁 API 返回"采纳/回退"结论，可直接进 CI |
| 成本中心 | 每次评测的 token 与花费入账，按任务/评估器/模型三维看 |
| stale 传播 | 迟到 span 到达后旧结论自动作废（revision 比较），看板分数恒定剔 stale |

**可信度机制**（写进文案，因为这是评测工具的可信度本身）：幂等键含样本级 attempt（重试/续跑/flaky 都不重复计数）、manifest 派发时冻结、1 attempt = 1 window、聚合恒剔 stale。

**地址配置**：源文件写 `{{EVALDECK_URL}}` token；本地档指向 `http://127.0.0.1:8902/`，生产用环境变量 `EVALDECK_URL` 覆盖为对外域名，不改源文件。守卫 **G16** 锁 iframe 嵌入完整性 + token 零残留。

**诚实边界**：评测平台是**独立部署的服务**，官网只做嵌入与品牌加载态；平台未启动时该页显示加载态而非假数据——不做静态快照冒充可用。

## 3. 逐屏设计

### ① 公告条

- **形态**：全宽单行，`--accent-weak` 底 + 1px 下边框，`--accent` 强调版本号
- **内容**：`v1.8.1 已发布 · 新增「AI 诊断评测闭环」：故障注入脚本即标注机，回放两次结论逐字段一致  看发布说明 →`
- **规则**：每版只推**一条**；有关闭状态（localStorage 存条目 id，不存版本号——版本号会变，用它当已读键会导致老用户永远看不到）；`patch` 级不打扰

### ② Hero

**结构**：左文右图，桌面 1.05 / .95 双栏，≤1000px 堆叠

**主张句**（沿用 README 首屏，已验证过效果）：
> 告警响了，AI 已经查完，**证据链摆在你面前。**

**副句**（一段话讲清"是什么 + 怎么做 + 边界在哪"）：
> 拉取式 **Agent** 接管主机与服务监控（被监控机**零入站端口**），告警收敛成事件后交给带**证据链**的诊断 Agent 自主排查取证；处置只在白名单内、经**九道护栏**准入后执行——**AI 负责把事实查清楚，拍板权在人。**

**三个 CTA**（主次分明，自助 > 销售）：
| 按钮 | 样式 | 去向 |
|---|---|---|
| 一键部署 | primary（实心蓝） | `/deploy` |
| 看一次真实诊断 | ghost | `#evidence` |
| 读文档 | ghost | `/docs` |

**三个真实数字**（这行的作用是替代 logo 墙）：

| 数字 | 标签 | 出处 |
|---|---|---|
| **82 秒** | 出带证据链的根因报告 | 一次真实故障处置实测 |
| **10 分钟** | 告警 → 恢复全流程 | 含审批与执行留痕 |
| **0 个** | 被监控机入站端口 | Agent 主动回连平台 |

> 三个数字全部来自真跑，不是宣传口径。每个数字下方一行 11px `--muted` 标注出处。

**主视觉：真实诊断报告片段**

不是产品截图（截图会过期），是**一段结构化的真实输出**：
- 头部：`status: succeeded · confidence: CONFIRMED · strength: moderate`
- Summary 一句
- **Evidence 三条，每条带可点 chip `step_3` / `step_4` / `step_7`** ← 视觉核心
- 底下 `What I ruled out` 一行（磁盘 38% / 证书 89 天 / 其它主机正常）
- 页脚：`16 步 · 12.3 万 tokens · 8 个只读工具` + 右侧「置信度按证据来源确定性计分」

> **为什么用报告而不是截图**：① 截图一改就过期；② 报告本身就是产品最强的差异化证明；③ 深色代码面板的视觉密度高，衬得住首屏。

### ③ 主链路四步

- 四张等宽卡，`--surface` 底 + `--border-soft` 边框 + hover 上浮 2px
- 每张：序号（mono 小字 `--accent`）+ 标题 + 一句 + 3 条要点
- 序号用 `STEP 01 / 发现` 格式（不是 1/2/3/4）

### ⑥ ★ 证据链专章（差异化核心）

**视觉**：整段 `--surface2` 底 + 上下 1px 边框，与其它区块形成节奏断点。

**左半（文案）**：
- 标题：**别人的 AI 给你结论，我们给你证据。**
- 引入段先承认问题："AI 写的报告最常见的失败不是写错，是**写得像对的**——业务码 0、状态字段 3、合作状态 1，看着全对，但你追问'这个 3 从哪来的'，它答不上来。"
- 5 条编号要点：
  1. 结论必须带证据 token
  2. 不确定就写不确定（确定性计分，不是模型自评）
  3. 反过早收敛（三条陷阱清单）
  4. 把没查的也说清楚（影响面四分类）
  5. 结论可复现（快照回放 + 温度 0）

## 4. 视觉系统

### 4.1 令牌：**直接复用平台 `static/ops.css`**

官网与产品**必须同一套语言**——访客从 GitHub 点进官网，再点进平台，视觉跳变等于两个产品。

| 组 | 令牌 | 值 |
|---|---|---|
| 底 | `--bg` | `#0e0f11`（暗）/ `#f2f2f7`（亮） |
| 面 | `--surface` / `--surface2` | `rgba(28,29,32,.72)` / `#1e1f23` |
| 边 | `--border` / `--border-strong` / `--border-soft` | 8% / 16% / 7% 白 |
| 字 | `--text` / `--muted` / `--skip` | `#f5f5f7` / `#9a9aa2` / `=` muted |
| 强调 | `--accent` / `--accent-rgb` / `--accent-hover` | `#2383e2` / `35,131,226` / `#1e6fcc` |
| 语义 | `--pass` / `--fail` / `--warn` | 绿 / 红 / 蓝（**D53b 定为正蓝**，历经琥珀→紫→青→正蓝） |
| 圆角 | `--radius-sm` / `--radius` / `--radius-lg` | 6 / 8 / 12 px |
| 阴影 | `--shadow-card` / `-hover` / `-pop` | 三档 |
| 缓动 | `--ease` | `cubic-bezier(.2,.7,.3,1)` |
| 字体 | `--font` / `--font-mono` | `-apple-system,"SF Pro Text","PingFang SC"` / `"SF Mono"` |

**派生档只引用 rgb 三元组**（`--accent-weak/.16/.20/.35`）——换色或换主题只改一处。这是平台 D50 收敛的核心纪律，官网沿用。

### 4.2 主题

- 默认**深色**（与平台一致）；右上角切换，明暗两套都是一等公民
- 持久化 `localStorage["aiops_site_theme"]`
- 每主题**各一档**语义色——深浅共用一个值必然在一侧失衡（平台 D50 的根因）

### 4.3 布局

- 内容宽 `--maxw: 1180px`，左右 padding 24px（移动 18px）
- 卡片栅格 `repeat(auto-fit, minmax(280px, 1fr))`
- 圆角：卡片 12px，按钮/输入 8px，chip 5-6px
- 边框 1px，卡片阴影极淡（`--shadow-card`）

### 4.4 动效

- 全部走 `--ease`，时长 .15-.18s
- hover：卡片上浮 2px + 边框转 `--accent-ring`；按钮上浮 1px
- **无入场动画、无视差、无渐变扫光**——这是 D130 那一轮被用户判"太AI了"的五种手法的反面
- `prefers-reduced-motion: reduce` 全局豁免
