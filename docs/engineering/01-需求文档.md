## 1. 目标与用户

**目标**：把单文件原型变成可扩展、可发布、可运营的多页官网，今日具备上线条件（P5 部署另计）。

**用户与各自要什么**：

| 用户 | 首次访问要看懂 | 回访理由 |
|---|---|---|
| 个人开发者（口碑引擎） | 这是什么、怎么跑起来 | 教程、题库、Agent 社区 |
| 小团队运维（主体） | 能不能解决我的问题、怎么部署 | 学习学院、月报 |
| 企业决策者（商业） | 凭什么可信、商业版差异 | VIP 权益、安全与审计叙事 |
| AI Agent / 搜索引擎 | 机器可读的页面与结构化数据 | sitemap、llms 友好的清晰结构 |

## 2. 范围

**做（In）**：P1 工程化 8 项 · P2 内容页 8 页 · P3 文档中心 3 项 · P4 SEO/体验 6 项。
**不做（Out）**：P5 部署上线（另一步）、后端/搜索/评论/i18n 英文版（结构预留不实现）、移动端深度适配（退化可用即可，平台本身不支持移动端）。

## 3. 功能需求（FR，编号 = 开发功能点，验收均为可测试语句）

### 3.1 P1 站点工程化（8 项）

- **FR-P1-1 公共样式层 `assets/site.css`**：从原型抽出全部令牌（`--bg/--surface/--accent/...` D50 口径，深浅双主题）与组件类（nav/footer/btn/card/tbl/faq/drawer/tab/skill-card/vip-mock/term 等全部现有类）。
  验收：原型拆出后浏览器渲染**零视觉回归**（对拍截图）；CSS 无 `!important`；令牌仅 `:root` 两处定义。
- **FR-P1-2 公共脚本层 `assets/site.js`**：主题切换（localStorage 持久化 + 跨页一致）、移动导航（如需）、FAQ `<details>` 无需 JS、社区三轨 tab 切换、（预留）返回顶部。
  验收：主题偏好跨页保持；tab 切换三轨互斥；`node --check` 通过。
- **FR-P1-3 页面生成器 `tools/build_pages.py`**：单一事实源驱动多页生成。
  - 输入：`site/src/layout.html`（骨架，含 `{{TITLE}}/{{DESC}}/{{CANONICAL}}/{{CONTENT}}` 槽位）+ `site/src/pages/*.html`（内容片段）+ 页面注册表（每页：slug/title/description/og 描述/所属导航组）；
  - 输出：`site/*.html`（**构建产物提交入库**，纯静态托管无需 CI 构建）；
  - 幂等：重复构建 diff 为空；`--check` 模式校验"产物与源一致"（防手改产物）。
  验收：`python tools/build_pages.py && git diff --exit-code site/` 通过。
- **FR-P1-4 导航与页脚组件化**：nav（品牌 + 7 链接 + GitHub star + 主题按钮 + CTA）与 footer（品牌列 + 5 栏 + 底行）为共享 partial，生成器注入每页；当前页导航项高亮。
  验收：任一页改导航，重建后全站一致；当前页 `aria-current="page"` 正确。
- **FR-P1-5 404 页**：品牌视觉 + 返回首页/看文档双入口。
  验收：访问不存在路径（静态托管配置后）返回 404.html；页内链接全部可达。
- **FR-P1-6 robots.txt + sitemap.xml**：sitemap 由页面注册表自动生成（含 lastmod=构建日期）；robots 允许全站、指向 sitemap。
  验收：sitemap 覆盖注册表全部页面且仅这些页面。
- **FR-P1-7 head meta 规范**：每页 `<title>`（模式：`{页名} · AIOps AI 运维监控平台`）、unique description、`og:title/og:description/og:type/og:image`、`canonical`。
  验收：扫描器断言每页四要素齐备且 description 唯一。
- **FR-P1-8 性能预算守卫 `tools/check_budget.py`**：每页 HTML+CSS+JS 合计 ≤ **150KB**（现状 70KB）；超限即失败并列出各资源体积。
  验收：P4 完成后全站页面过预算。

### 3.2 P2 内容页（8 页，每页列出核心功能点）

- **FR-P2-1 `/features/` 功能详解**：
  四章（发现/定位/处置/沉淀）展开首页能力四块，每章含：FR 映射表（产品 FR 编号）、机制要点（来自 03 详细设计：指纹状态机/收敛/护栏五层/凭据单次有效等）、1 组真实数字。验收：全部数字在数字来源表有出处。
- **FR-P2-2 `/evidence/` 证据链专页**：
  区块：① 一次真实处置全时间线（82 秒报告/10 分钟恢复/16 步/12.3 万 tokens）② 报告解剖（Summary/Evidence/What-I-ruled-out/四分类 impact）③ 评测闭环（快照回放/temperature=0/调优池与回归池隔离）④ "不编造"红线叙事（PENDING 机制）。验收：每条证据引用带 `step_N` 视觉锚点；无准确率类表述（扫描器）。
- **FR-P2-3 `/deploy/` 部署指南**：
  三路径卡（开源 Docker/私有化/商业）+ 快速开始命令块（与产品仓 `快速开始.md` **逐字一致**，由构建器从产品仓源文件抽取命令块，不手抄）+ 前置条件 + 故障注入脚本介绍（含"勿在生产机运行"警示）+ 常见问题（--env-file 必带等实测坑）。验收：命令一致性对账脚本通过；警示文案存在。
- **FR-P2-4 `/learn/` 学习学院主页**：
  3 学习路径卡（值班工程师 4 周/中级 SRE 6 周/平台开发者 8 周，来自 `learning/paths/`）+ 4 栏目入口（各栏目文章清单）。验收：文章数与源文件数一致（11 篇机制/SRE 文章 + 12 教程 + 46 题）。
- **FR-P2-5~8 `/learn/` 4 个栏目页**：
  aiops（4 篇）/ sre-basics（4 篇）/ tutorials（12 篇目录）/ interview（46 题目录）。文章卡：标题 + 一句话 + 阅读时长（按字数估算）+ 外链 GitHub 正文。验收：目录页零死链；`learning/` 源文件增删后重建即同步（生成器读目录）。
- **FR-P2-9 `/agent-community/` Agent 社区页**：
  三轨 tab（官方 8/社区种子 8/集成配方征集）——**社区与官方技能卡由构建器解析 `agent-community/skills/*.md` frontmatter 自动渲染**（name/description/alerts/commands 数量），新增技能文件重建即上站；贡献三步；贡献者墙空态；月度效果榜样本不足态；安全前置条。验收：删除任一技能 md 重建后卡片消失；卡片数据与 md 内容一致（抽查断言）。
- **FR-P2-10 `/oss-hub/` 开源专区页**：
  8 上游/互补项目 + 收录规则说明 + 每月复核声明。验收：零竞品名（扫描器）。
- **FR-P2-11 `/vip/` VIP 权益页**：
  定时任务完整版（4 模板卡 + 创建表单预览 + 门禁说明 License `pro`）+ **"即将上线"标识（不可移除，扫描器断言）** + 首批体验名单入口（mailto）+ VIP 权益总览（源设计稿 8 权益精简为当前实际 4 项：定时任务/源码授权/1V1/优先响应——只列已确定项，不虚列）。
- **FR-P2-12 `/about/` 关于页**：
  版本号（构建器读产品仓 `VERSION` 注入）+ 路线图（V1 已交付/V2 远程执行通道）+ 贡献入口 + 安全通告渠道。验收：版本号与产品仓一致（对账断言）。

### 3.3 P3 文档中心（3 项）

- **FR-P3-1 `/docs/` 文档中心主页**：三栏布局（左导航/正文/右目录，复用产品 FR-420 交互规范：跳转+滚动高亮+≤1280px 退化两栏）；入口卡：快速开始/API 参考/教程 12 篇/排障手册。
- **FR-P3-2 API 参考页**：构建时从产品仓运行 `gen_api_doc.py` 产物复制（或链接），标注"机械生成勿手改"。
- **FR-P3-3 教程正文页 `/docs/tutorials/{01..12}.html`**：`docs/05-教程/*.md` 经 vendored marked.js 渲染为静态 HTML（构建器执行），代码块等宽样式；文首"适用版本"取源 md frontmatter。
  验收：12 篇全部生成；抽样 3 篇正文与 md 一致；图片路径可用（相对拷贝）。

### 3.4 P4 SEO 与体验（6 项）

- **FR-P4-1 OG 分享图**：1200×630 PNG ≤150KB，双专色印刷风（沿用 D132 印刷品语言，禁渐变发光），由浏览器渲染 OG 模板页截图产出；入 `assets/og/`。
- **FR-P4-2 结构化数据**：首页 `SoftwareApplication` + `/faq` 相关 `FAQPage` + 站级 `Organization` JSON-LD。
- **FR-P4-3 可访问性**：全站焦点环可见、键盘可导航（tab 序）、交互件 aria 标签、正文对比度 ≥4.5:1（浅深两主题各测关键组合）、`prefers-reduced-motion` 豁免。
- **FR-P4-4 响应式回归**：1440/1024/768/390 四档，全站零横向溢出（浏览器实测断言）。
- **FR-P4-5 sitemap/robots/llms.txt**：补 `llms.txt`（机器可读站点摘要：产品定位/主要页/文档入口），占 Agent 入口位。
- **FR-P4-6 数字与诚实审计**：`tools/sensitive_scan.py` 扩展两条——数字来源审计（关键数字须在来源表登记）、诚实标识审计（`/vip` "即将上线"存在且无"已上线"字样）。

## 4. 非功能需求

| 类 | 要求 |
|---|---|
| 性能 | 单页（HTML+CSS+JS）≤150KB；无外部请求（零 CDN）；字体系统栈 |
| 安全 | 零第三方脚本；无内联事件以外的动态注入面；表单仅 mailto |
| 内容 | 禁用词表（竞品名/准确率/无人值守/无授权 logo）全站零命中 |
| 兼容 | 现代浏览器（Chrome/Safari/Edge/Firefox 近两年版本）；移动端退化可用 |
| 可维护 | 全部页面由构建器生成，**禁止手改产物**（`--check` 守卫） |
